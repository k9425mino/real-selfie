## 1. 배경 및 문제 정의

본인이 **비반전 실시간 화면으로 얼굴 전체 모습을 확인**하기 위해 시작한 앱이다. 익숙한 거울 화면과 달라 얼굴의 위치와 각도를 의도대로 잡기 어려운 점을 얼굴 추적 박스와 고정 격자로 보조한다.

개인 사용에서 출발했지만 다양한 사용자가 만족할 수 있는 품질을 목표로 하며, 학습·포트폴리오와 스토어 출시로 이어간다. 기본 카메라 전체에 해당 기능이 없다고 단정하지 않는다.

모드 이름은 **실물 / 거울**을 사용한다. 실물은 좌우가 반전되지 않은 화면을 뜻하며, 실제 대면 모습과의 완전한 동일성을 의미하지 않는다. 촬영 거리·각도 등에 따른 차이는 앱 소개·스토어 설명에 안내하고, 앱 내 첫 실행 설명은 두지 않는다.

## 2. 목표 / 비목표

### 목표
- 전면 카메라 프리뷰를 **실시간 비반전(실물)** 으로 보여준다.
- 실물 ↔ 거울 모습을 빠르게 번갈아 보여주는 **좌우반전 챌린지 모드**로 얼굴 좌우 비대칭을 체감하게 한다.
- 얼굴 추적 박스와 3×3 가이드선으로 **비반전 화면에서 얼굴 위치와 움직임 파악을 보조**한다. 방향 지시나 비대칭 측정은 하지 않는다.
- 화면에 보이는 그대로(실물 또는 거울) 촬영해 갤러리에 저장하고 공유할 수 있다.

### 비목표 (MVP 범위 외)
- 동영상 촬영
- 필터 / 뷰티 보정
- 챌린지 모드 결과물 저장 (GIF·영상)
- 앱 내 갤러리 / 촬영 후 편집 화면
- 계정, 서버, 클라우드 저장
- 광고·유료 기능

## 3. 타겟 사용자 및 시나리오

| 페르소나 | 시나리오 |
|---|---|
| 얼굴·스타일 확인 (주목적) | 비반전 실시간 화면으로 얼굴 전체·헤어·표정을 확인하고 박스와 격자를 보며 위치를 조정 |
| 실물·거울 비교 | 챌린지로 두 모습의 차이를 확인 |
| 셀카 저장·공유 | 선택한 모드와 프리뷰 범위대로 촬영해 저장·공유 |

## 4. 기능 요구사항

### F1. 실시간 비반전 프리뷰 (핵심) — P0
- 앱 실행 시 전면 카메라로 바로 시작한다. **최초 실행은 실물(비반전) 모드**, 이후에는 **마지막으로 사용한 모드(실물/거울)** 로 시작한다.
- 카메라 화면 비율은 **3:4**, 화면 방향은 **세로 고정**. 작은 화면·큰 글자 설정에서는 프리뷰를 줄여 모든 조작 버튼을 화면 안에 배치한다.
- 토글 버튼으로 **실물 ↔ 거울** 모드를 전환한다.
- 현재 모드를 화면에 명확히 표시한다 (예: `실물` / `거울` 라벨).
- 전화 등으로 카메라가 중단되면 사용 가능한 상태에서 자동 복구하고, 실패 시 재시도 버튼을 표시한다.
- 카메라 프리뷰 사용 중에는 화면 자동 꺼짐을 방지한다. 사용자가 직접 화면을 잠그는 것은 허용하며, 앱 비활성화·카메라 중단 시 화면 켜짐 유지를 해제한다.

### F2. 좌우반전 챌린지 모드 — P0
- 버튼으로 진입/종료한다. **실시간 프리뷰 전용**이며 촬영·저장할 수 없다 (셔터 비활성화).
- 실물 프리뷰와 거울 프리뷰를 일정 간격으로 번갈아 표시한다.
- 전환 간격은 슬라이더로 조절: **0.10초 ~ 1.00초, 0.05초 단위, 기본값 0.25초**.
- **빠른 화면 전환에 대한 광과민성 경고**를 진입 시마다 표시한다. "다시 보지 않기"를 선택하고 확인하면 이후 생략한다. 취소하면 챌린지는 시작하지 않는다. 경고 문구의 정확한 내용은 추가 검토한다.
- 챌린지 모드 중에도 얼굴 박스는 표시되는 이미지 기준으로 올바른 위치에 그려져야 한다.
- 모드 라벨은 `챌린지`로 고정한다. 실물/거울 수동 전환은 비활성화하고, 얼굴 박스·격자 토글과 속도 조절은 허용한다.
- 종료하면 시작 전 모드로 복귀한다. 다른 앱 이동·화면 잠금·카메라 중단 시에도 종료하며 자동 재개하지 않는다.
- 촬영·저장 처리 중에도 진입할 수 있다. 진행 중인 사진 저장은 촬영 시점의 정보로 계속 처리한다.

### F3. 3×3 가이드선 — P0
- 카메라 화면 전체에 고정된 3×3 격자선을 오버레이한다.
- 별도 토글로 켜고 끌 수 있다. 최초에는 ON, 이후 마지막 설정을 기억한다.
- **프리뷰에만 표시**하며 저장되는 사진에는 포함하지 않는다.

### F4. 얼굴 인식 박스 — P0
- 실시간으로 얼굴을 인식해 얼굴 영역에 사각형 테두리를 그린다.
- 인식은 **온디바이스**에서만 처리한다 (이미지 외부 전송 없음).
- 반전 상태(실물/거울/챌린지)에 맞춰 박스 좌표도 반전되어야 한다.
- 격자와 독립된 토글로 켜고 끌 수 있다. 최초에는 ON, 이후 마지막 설정을 기억한다. 저장 사진에는 포함하지 않는다.
- 여러 얼굴이 인식되면 모두 표시한다.
- 얼굴이 인식되지 않으면 박스만 숨기며 별도 안내 없이 프리뷰·격자를 유지한다.
- 인식 기능 자체에 오류가 생기면 안내 후 박스만 중지한다. 다른 기능은 유지하고 얼굴 박스 토글로 재시도한다.
- 프리뷰의 부드러움을 우선하며, 성능 부족 시 얼굴 박스 갱신 빈도를 자동으로 낮추되 추적은 유지한다.
- 얼굴 박스는 약간의 추적 지연을 허용하더라도 떨림을 줄이고 부드럽게 따라가도록 한다. 구체적인 지연 허용치는 실기기 사용 평가로 정한다.
- 박스와 격자는 고정 스타일로 제공한다. 색상·두께·투명도 설정은 제공하지 않으며 실제 프리뷰에서 가독성과 얼굴 가림을 확인해 조정한다.

### F5. 사진 촬영 / 저장 — P0
- 셔터 버튼으로 촬영, **시스템 갤러리에만 저장**한다 (앱 내 갤러리 없음).
- 저장 이미지는 3:4 비율, **촬영 시점의 좌우 방향과 프리뷰에 담긴 범위까지 일치**해야 한다. (WYSIWYG; 오버레이 제외)
  - 실물 모드에서 촬영 → 실물(비반전) 이미지로 저장
  - 거울 모드에서 촬영 → 거울(반전) 이미지로 저장
- **챌린지 모드에서는 셔터를 비활성화**한다 (프리뷰 확인 전용).
- 선택한 카메라에서 지원하는 최대 사진 해상도를 사용하되, 프리뷰 범위와 3:4 비율을 맞추기 위한 크롭은 허용한다.
- 최대 사진 해상도와 부드러운 프리뷰를 모두 목표로 한다. 동시에 충족하기 어려운 경우에는 최대 해상도를 우선하고 촬영·저장 중 일시적인 프리뷰 끊김을 허용한다는 잠정 방침을 적용한다. 실제 사용 후 재평가하며 평상시 프리뷰 성능 기준을 낮추는 의미는 아니다.
- 첫 촬영 시 필요한 저장 권한을 먼저 요청한다. 허용되면 촬영하고, 거부하면 촬영하지 않고 프리뷰를 유지한다.
- 촬영 작업을 접수할 때 모드·촬영 범위를 고정한다. 처리 중 추가 촬영만 차단하며 실물/거울 전환과 챌린지 시작은 허용한다.
- 촬영 순간 짧은 시각 효과·햅틱을 제공한다. 저장 처리 중에는 `저장 중…`, 성공하면 `저장됨`을 표시한다.
- 저장 실패 시 미저장 상태를 명확히 표시하고 사진을 임시 유지한다. 썸네일 옆에 `저장 재시도` 버튼을 표시하며, 썸네일 탭으로 공유할 수 있다.
- 미저장 사진이 있어도 새 촬영을 허용하며, 새 사진이 촬영되면 확인 없이 교체한다.
- 다른 앱 이동 후에도 이미 촬영한 사진은 앱이 실행 가능한 동안 저장을 계속 시도한다. 앱 프로세스 종료 후 미저장 사진 복구는 제공하지 않는다.

### F6. 공유 — P0
- 촬영 후 하단에 **최근 촬영 사진 썸네일**을 표시한다.
- 썸네일 탭 → **OS 기본 공유 시트**를 호출한다.
- 최근 사진은 이번 프로세스 실행 중 촬영한 마지막 사진만 표시한다. 다른 앱 이동·화면 잠금 시 유지하고 프로세스가 종료되어 새로 시작하면 초기화한다. 갤러리에 저장된 사진은 유지한다.

### F7. 다국어 — P0
- 한국어 / 영어 지원. 기기 언어에 따라 자동 선택.

## 5. 화면 구성 (단일 화면)

- 카메라 주변 배경·버튼은 어두운 테마로 고정한다. 기기의 밝은/어두운 테마 설정을 따르지 않으며 프리뷰·저장 사진의 밝기에는 영향을 주지 않는다.

```
┌─────────────────────────┐
│ [실물]        [⊞] [👤]  │  ← 모드 라벨 / 가이드선 토글 / 얼굴박스 토글
│ ┌─────────────────────┐ │
│ │   ┊       ┊         │ │
│ │ ┈┈┼┈┈┈┈┈┈┈┼┈┈┈┈     │ │
│ │   ┊ ┌───┐ ┊         │ │  ← 3:4 프리뷰
│ │   ┊ │ ☺ │ ┊         │ │     + 3×3 격자 + 얼굴 박스
│ │ ┈┈┼┈└───┘┈┼┈┈┈┈     │ │
│ │   ┊       ┊         │ │
│ └─────────────────────┘ │
│  [챌린지 속도 슬라이더]    │  ← 챌린지 모드일 때만 표시
│                         │
│ [썸네일]  ( ◉ )  [⇄][⚡] │  ← 최근사진 / 셔터 / 실물↔거울 / 챌린지
└─────────────────────────┘
```

## 6. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 성능 | 60fps 지원 기기는 일반 조명에서 촬영·저장 작업이 없는 프리뷰의 60fps 유지 필수. 얼굴 박스·격자·챌린지 사용에도 적용하며 얼굴 인식 빈도를 조절해 프리뷰를 우선한다. 60fps 미지원 기기도 사용을 허용하고 30fps 등 지원 가능한 프레임률로 동작한다. 측정 조건·허용 오차는 별도 확정 |
| 저조도 | 어두운 환경에서는 얼굴이 밝게 보이는 것을 우선하고 필요한 프레임 저하를 허용한다. 일반 프리뷰의 60fps 기준과 별도로 검증 |
| 성능 | 챌린지 간격 정확도와 장시간 사용 성능을 측정한다. 허용 오차는 검증 전 확정할 항목 |
| 연속 사용 검증 | 5분 동안 프리뷰·얼굴 추적 사용 시 발열과 끊김 변화를 확인한다. 사용 시간 제한은 아님 |
| 시작 시간 | 카메라 권한이 이미 허용된 S23 / Android 16에서 앱 실행 후 프리뷰 표시까지 3초 이내를 목표로 검증 |
| 저장 시간 | S23에서 최대 해상도 촬영 후 갤러리 저장 완료까지 측정하고 직접 사용해 본 뒤 허용 시간을 결정한다. 현재 수치 기준은 미확정 |
| 개인정보 | 앱 자체는 사진·얼굴 인식 결과·사용 기록을 수집하거나 서버로 전송하지 않는다. 사용자가 공유할 때만 선택한 앱에 사진을 전달 |
| 권한 | 카메라는 앱 실행 직후 시스템 권한 요청. 저장 권한은 첫 촬영 전에 요청. 저장 권한 거부 시 프리뷰·가이드·챌린지는 유지하고 촬영 시 권한 안내 |
| 호환성 | 상호 호환되는 최신 안정 기술 스택의 지원 범위에 맞춰 최소 OS 확정. 구형 OS 지원을 위한 버전 하향은 우선하지 않음 |
| 접근성 | 버튼 접근성 라벨 제공, 광과민성 경고 |
| 설정 유지 | 앱 재실행 시 유지: 실물/거울 모드, 챌린지 속도, 가이드선·얼굴박스 토글, 광과민성 경고 '다시 보지 않기' |

## 7. 기술 고려사항

- **프리뷰 성능**: 60fps 지원 기기의 일반 프리뷰는 60fps 유지가 필수다. 저조도에서는 얼굴 밝기, 촬영·저장 중에는 최대 사진 해상도를 우선하는 예외를 유지한다. 60fps 미지원 기기도 제외하지 않고 30fps 등 해당 기기에서 지원 가능한 프레임률로 동작한다.
- **Expo + Development Build 필요**: 실시간 얼굴 인식·카메라 프레임 처리는 네이티브 모듈이 필요해 Expo Go로는 불가. EAS Build 사용.
- **카메라 라이브러리 후보**: `react-native-vision-camera` + ML Kit 기반 얼굴 인식 플러그인 (예: `react-native-vision-camera-face-detector`). `expo-camera`는 실시간 얼굴 인식 지원이 제한적이라 비교 검토 필요.
- **비반전 프리뷰 구현**: 비반전 출력을 기준으로 프리뷰와 얼굴 박스를 함께 반전한다. API·출력 방향·좌표계는 **실기기 검증 필수**이며 세부 설계는 TECH_SPEC을 따른다.
- **저장 이미지 방향**: 촬영 결과물의 기본 미러링 여부도 플랫폼별로 다르므로, 저장 전 반전 여부를 명시적으로 처리.
- **챌린지 모드**: 카메라 스트림을 재시작하지 않고 뷰의 `transform`만 토글해 성능 확보.
- **저장/공유**: `expo-media-library`, `expo-sharing` (또는 RN Share API).
- **다국어**: `expo-localization` + i18n 라이브러리.

## 9. 검증 순서 및 성공 지표

- 정해진 출시 기한은 없다. 본인이 직접 사용하며 충분히 만족하는 완성도에 도달한 뒤 지인 테스트와 출시를 진행한다.
- **갤럭시 S23 / Android 16** 위주로 개발하고 본인이 먼저 테스트한다. 충분히 완성되면 지인 테스트를 진행한다. 초기 다기기 확보나 고정 기기 대수는 필수 조건으로 두지 않는다.
- 다양한 사용자의 만족이 제품 품질 목표다. S23 검증 결과를 전체 기기의 검증 완료로 간주하지 않고, 지인 테스트에서 기기·OS·결과를 기록한다.
- Android를 먼저 출시하고 iOS는 실제 기기 검증을 완료한 뒤 출시한다.
- 저장된 사진이 촬영 시점 프리뷰와 좌우·세로 방향·촬영 범위가 일치하고 3:4 비율을 유지한다.
- 실물/거울/챌린지, 가이드, 권한 거부, 저장 실패·재시도, 카메라 중단·복귀가 정의한 동작과 일치한다.
