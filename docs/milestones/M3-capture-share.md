## 목표

화면에 보이는 그대로(모드·범위·3:4) 촬영해 갤러리에 저장하고, 실패 시 재시도하며, 썸네일로 공유할 수 있다.

## 작업

- [ ] `capture.ts` 로직: 작업 잠금, 접수 시 모드·크롭 고정, 촬영·후처리 실패와 저장 실패 구분, 같은 파일 재시도. 단위 테스트 포함 (§7, §11.1)
- [ ] 저장 권한 흐름: 첫 촬영 전 확인·요청, 거부 시 촬영 없이 안내 (§8, §15 #2)
- [ ] 후처리 파이프라인: orientation 정규화 → 크롭 → 거울 모드면 좌우 flip → 갤러리 저장. M1 결과를 따른다 (§7)
- [ ] 셔터 UI: 시각 효과, 햅틱, `저장 중…` / `저장됨` 표시
- [ ] 최근 사진 썸네일, 공유 시트, `저장 재시도` 버튼 (F6)
- [ ] 임시 파일 정리: 최근 파일·진행 중 참조 파일 유지, 재시작 시 잔여 캐시 정리 (§7)

## 완료 조건

- [ ] CI: `capture.ts` 단위 테스트 통과
- [ ] (실기기) 글자·가장자리 표식으로 양 모드의 좌우·세로 방향·프레임 경계가 프리뷰와 일치하고 3:4이며 오버레이가 없다
- [ ] (실기기) 실물로 촬영 직후 거울로 전환해도 결과는 실물이다 (반대 방향도 확인)
- [ ] (실기기) 셔터를 연타해도 중복 촬영이 없다
- [ ] (실기기) 저장 권한 거부 시 촬영하지 않고 프리뷰가 유지된다
- [ ] (실기기) 개발용 실패 주입으로 저장 실패 → 미저장 표시 → 재시도 → 공유를 확인한다
- [ ] (실기기) 썸네일이 다른 앱 이동 후에도 유지되고 프로세스 재시작 시 사라진다
- [ ] (실기기) 저장 시간과 촬영·저장 중 프리뷰 끊김을 측정한다 (§15 #15, #16)
